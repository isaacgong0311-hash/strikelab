# Pilot Observation Notes

What you see during meetings, check-ins and interviews, keyed to where in the product it happened. This file feeds three decisions:
- which bottleneck to fix each week (master plan §6 decision rules);
- whether bite-sized sessions beat long-form lessons (the W10 format check);
- facilitator guide v2 (master plan G5).

**Rules:** one row per observation, written the same day. Use the lesson or session id and the step id when you know them (the session player's URL is `/learn/<session id>`). Write what happened, not your interpretation. Put the interpretation in the last column. Never write a student's full name: use initials plus the cohort letter (e.g. `A-JK`).

## Patterns to watch for

- **Joining:** mistyped emails, confirmation emails in spam, confusion between "join code" and "invite link", students under 13.
- **The first session:** where students hesitate the longest; questions answered wrong on the first try by many students (likely a wording problem, not a knowledge problem).
- **Code weeks (3–5):** Python loading time on school devices; errors students can't read; which function they get stuck on.
- **Between meetings:** who does work outside the meeting at all, and when (the scorecard's weekly activity shows it).
- **The leader:** what they asked the founder for (each ask is a candidate for the leader toolkit, master plan A9), and what they skipped in the facilitator guide.
- **Capstones:** which prompt students pick, and where they stall (thesis, code or reflection).
