# StrikeLab: YC product review

Reviewed October 21, 2026. Scope: repository implementation and official YC company profiles; the public homepage was also inspected at https://strikelab.dev/. No production database, payment dashboard, customer interviews, or authenticated deployed journeys were verified. This is a product judgment, not an admission forecast.

## Verdict

StrikeLab is a substantial pilot product with an unproven business. The code is already broad enough to run customer discovery and pilots. More feature breadth will not resolve the main uncertainty: whether independent leaders repeatedly run the lab, students learn and return, and a buyer pays to continue.

The strongest initial pitch is: **StrikeLab helps high-school clubs teach technical finance through browser-based coding labs, with a weekly meeting plan and inspectable student projects.** Keep the club as the initial distribution wedge; expansion into other applied STEM labs is a hypothesis until clubs retain and pay.

The retrieved public homepage uses a student-and-leader split hero, while this local checkout uses a clubs-first hero. Treat this as a deployment/source mismatch to reconcile before shipping; the local changes in this review have not been deployed.

## Current readiness

| Dimension | Assessment | Evidence / limit |
| --- | --- | --- |
| Product depth | Strong for a pilot | 23 lessons, in-browser Python, pricing visualizer, short sessions, cohorts, capstones and scorecards exist. Existence is not live reliability. |
| Customer clarity | Focused offer, unvalidated buyer | Club leaders and instructors have a six-week offer. The user, champion, approver and payer may differ. |
| Activation | Useful existing practice, improved entry | First lesson works without signup; new `/start` recommends a starting lesson from four explained questions. No conversion uplift has been measured. |
| Retention and outcomes | Unknown | Cohort metrics and capstones exist; baseline values and real cohort evidence remain unknown. Short-session coverage is limited to three lessons. |
| Commercial proof | Unknown | Stripe implementation and displayed prices are not payment evidence. |
| Differentiation | Promising hypothesis | Writing and explaining models is a more specific outcome than a generic investing game. Interviews must establish whether buyers care enough to switch. |
| Market scale | Unproven | Clubs offer a reachable entry point. A venture-scale expansion case needs bottom-up buyer counts, budget, acquisition economics and evidence of repeat use. |
| Founder story | Relevant | A student building a tool for a problem they experience is useful context. Pair it with dated customer learning and shipped iterations. |

A brokerage account, broad AI tutor, public leaderboard, or a large new curriculum would create additional operational work without validating this wedge. No new AI provider, external account or paid service is needed for the current change.

## Changes made in this pass

- Added `/start`: four concept questions, immediate explanatory feedback, an uncertainty option, and an explicit recommendation based on the earliest gap. All-correct answers lead to the existing Black-Scholes lesson. Every destination remains available regardless of score.
- The check is explicitly informal: no course credit, validated placement claim, stored assessment record or teacher visibility. Answers remain in page memory; leaving resets them.
- Added a homepage entry and sitemap discovery. Kept the leader pilot as the primary homepage action.
- Replaced guaranteed capstone completion, absolute zero-preparation wording, and the broad “safe for school” heading with more supportable wording.

## Next evidence to collect

1. Recruit three independent club leaders for the existing pilot. Record their current alternative, next meeting date, approver and prospective payer. Three is an operating target, not a YC admission requirement.
2. Watch first-use sessions. Measure where learners stop before their first completed exercise. Compare the new check with direct first-lesson entry using an explicitly defined experiment; a correct answer on the check does not count as activation.
3. Run the existing six-week program. Export denominators for enrolled, activated, weekly active, mature week-four retained, and capstone submitted students. Keep teacher activity separate from student activity.
4. Collect one baseline task and one unseen follow-up task assessing the same skill. Report matched counts, results and missing follow-ups; this is descriptive learning evidence, not a causal claim.
5. Ask leaders whether they will run another cohort and present the actual continuation price. Separate interest, signed commitments and money received.
6. Before submitting YC material, reconcile all numbers against the claim ledger and payment records. The existing visitor figure from prior conversations is not a verified current metric.

[YC's growth guidance](https://www.ycombinator.com/blog/advice-on-organizing-and-running-growth-teams-from-dan-hockenmaier-and-gustaf-alstromer/) connects acquisition, activation, retention, referrals and monetization. For StrikeLab, instrumenting that chain and observing pilots is more useful than accumulating features that resemble funded companies.
